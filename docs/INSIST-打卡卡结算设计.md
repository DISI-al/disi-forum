# INSIST · 打卡卡结算与进化 设计方案（v2）

> 拍板人：DISI　·　整理：2026-11-03
> 状态：方案确认中，周末实施

## 0. 术语对齐

| 叫法 | 含义 | 内部字段 |
|---|---|---|
| **打卡卡** | 需要按天打卡的卡（不是"习惯"，就是一个卡种） | `kind = 'habit'`（暂不改库，只改文案） |
| **任务卡** | 一次性完成、有明确交付物的卡 | `kind = 'task'` |
| **技能** | 长期资产，卡片的 XP 都汇入技能 | `insist_skills` |

> 注意：现有卡片详情页有一句「…XP 锁定、重要度 −1」的旧文案，**与最终方案冲突，必须删掉**（重要度不再由系统改动）。

## 1. 核心原则（本次拍板）

1. **系统不碰技能重要度**。重要度是用户对"当前阶段、当前环境"的判断，只由用户自己改。
2. **结算只结算经验值**：把这张卡已经产出的 XP 锁定，卡片退场，不再产生任何 XP。
3. **打卡卡结算后 = 一张已完成的「任务卡」**：
   - 从打卡卡列表 / 今日打卡 / 进行中**消失**；
   - 出现在**技能详情的「已完成」**里，可查到"xx 天打卡"的记录。
4. **成就按标准发放，且有等级**（tier 1–4），不同达成路径给不同等级。

## 2. 状态机

```
                  ┌── 连续满 cycle_days ──► 自动结算（完美）
active(打卡卡) ───┤
                  ├── 累计满 cycle_days ──► 自动结算（补满）
                  │
                  └── 手动「提前结算」───► 手动结算（归档型）
                                │
                                ▼
                    原地转换：kind → task, status → done
                    detail ← "30 天打卡（连续 30 天）"
                    xp 锁定为累计值，settled_at / reason 落库
                    → 技能详情「已完成」可见，打卡列表消失
```

## 3. 判定规则

### 3.1 自动结算（两种都自动）

| 路径 | 判定 | 说明 |
|---|---|---|
| **完美** | `streak ≥ cycle_days` | 计划期内一天不断，最高档成就 |
| **补满** | `total_days ≥ cycle_days`（断过但总量够） | 也自动结算，成就降一档，detail 标注"累计" |

> 触发点：每次打卡成功后立即判断，命中则当次返回里带上结算结果，前端弹"已完成结算"。

### 3.2 手动结算

- 位置：打卡卡详情页的「提前结算」按钮；
- 允许条件：`total_days ≥ 1`（至少打过一次卡）；
- 交互：确认弹窗，显示「已获得 xx XP 将被锁定，卡片转为已完成任务卡」；
- 结果：转成已完成任务卡，`settle_reason = 'manual'`，成就按实际天数给"阶段成果"档。

### 3.3 卡片的字段变化

```
kind:        habit → task
status:      active → done
title:       不变（例：计算机学习）
detail:      自动生成，例：30 天打卡（连续 30 天，累计 30 天）
xp_value:    锁定为打卡累计 XP
locked_xp:   同上（快照，便于展示与回溯）
settled_at:  结算时间
settle_reason: perfect | filled | manual
```

结算后：**不能打卡、不能完成、不能改周期**，只允许删除。

## 4. 成就阶梯（tier 1–4）

| 事件 | 触发 | 等级规则 |
|---|---|---|
| 连续满 7 / 14 / 30 / 60 / 90 天 | 自动（完美） | 7→tier1、14→tier2、30→tier3、60/90→tier4 |
| 累计满 7 / 14 / 30 / 60 / 90 天 | 自动（补满） | 比完美低一档 |
| 阶段成果 7 / 14 / 30 天 | 手动结算 | 最高 tier2 |
| 已有：连续 7/30/100、累计 30/100/150/200 | 保留 | 不冲突（标题去重已实现） |

> 成就 = 完成记录 + 等级，用于成就墙分组展示；不参与 XP 计算。

## 5. 接口

```
POST /cards/{id}/settle
  body: { reason: 'manual', note?: string }
  → { card, lockedXp, awards: [...] }

POST /cards/{id}/checkin
  → 原有字段 + { settled: false | { path: 'perfect'|'filled', card, awards } }

GET /cards?status=done        # 已完成（含进化来的任务卡）
GET /cards?status=active      # 进行中（打卡卡 + 任务卡）
```

## 6. 数据字段（新增）

```python
settle_reason = Column(String(12), nullable=True)  # perfect | filled | manual
settled_at    = Column(DateTime, nullable=True)
locked_xp     = Column(Float, nullable=True)
```

`kind` 不新增枚举值：打卡卡仍叫 `habit`，只是文案统一改成「打卡卡」；若要彻底改名（`checkin`），需要一次数据迁移，**暂不做**。

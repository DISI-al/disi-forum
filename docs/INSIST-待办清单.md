# 一、周末必做（4 项）

## 1. 打卡卡结算（手动 + 系统）　★本次核心

### 1.1 打卡卡结算

| 路径 | 触发 | 结果 |
|---|---|---|
| **系统结算·完美** | 打卡后 `streak ≥ cycle_days` | 自动转任务卡（已完成），成就最高档 |
| **系统结算·补满** | 打卡后 `total_days ≥ cycle_days`（断过） | 自动转任务卡（已完成），成就降一档 |
| **手动结算** | 详情页「提前结算」按钮 | 转任务卡（已完成），`detail` 自填，给「阶段成果」档成就 |

结算动作（原地转换，不新建卡）：

```
kind:          checkin → task
status:        active → done
title:         不变（例：计算机学习）
detail:        用户自填；留空自动生成「30 天打卡（连续 30 天，累计 30 天）」
xp_value:      锁定为打卡累计 XP
locked_xp:     快照（展示用）
settled_at / settle_reason: perfect | filled | manual
```

结算后：不能打卡 / 不能完成 / 不能改周期，**只能删除**；卡片从「今日打卡 / 进行中」消失，出现在**技能 → 关联经验卡 → 已完成**。

### 1.2 任务卡：**保持现状，不改**

任务卡本来就是「用户手动点完成 → 一次性结算」，这个设计已经够好：

| 路径 | 触发 | 现状 |
|---|---|---|
| 结算 | 用户点「完成」 | 状态 done、一次性发 XP、记 `done_at` ✅ 不改 |

本次只处理「打卡卡 → 任务卡」的转换，任务卡的结算逻辑一行不动。

### 1.3 必须一起改的

- 删除打卡卡详情页旧文案「…XP 锁定、重要度 −1」（系统不改重要度）；
- `cycle_days` 必填（前端不给默认值，后端 schema/模型非空）；
- `kind` 改名：`habit → checkin`，表 `insist_habit_logs → insist_checkin_logs`；
- 打卡日志加唯一约束 `(card_id, day)`（bug #001）。

**验收**：连续打满 30 天 → 自动变已完成任务卡；打 7 天手动结算 → 归档且 XP 保留；两者都能在技能详情看到；结算后改周期被拒绝。

## 4. 移动端：背景板铺不满 + 下拉刷新

### 4.1 背景板铺不满（上下灰色区域）

**现象**：滚动到顶部/底部时露出灰色区域，背景色没铺满屏幕。

**判断**（待复现确认）：`body` 上加了安全区 padding，`html` 没有背景色；滚动越界时露出 WebView 底色。

**修复**：

```css
html, body { background: <应用底色>; }   /* forum #0d1117 / insist #050505 */
body { min-height: 100%; overscroll-behavior-y: contain; }
```

- 安全区改在容器上做，别放 `body`；
- Capacitor `backgroundColor` 与页面底色核对一致；
- iOS 容器层背景色补齐。

### 4.2 下拉刷新

**方案**：注入层实现（不动业务代码）

```
touchstart（scrollTop === 0，单指）→ 记起点
touchmove → dy > 60px 显示指示条
touchend → 达阈值触发 window.dispatchEvent(new Event('disi:refresh'))
        → 各页面监听后重拉数据（首页 / 卡片 / 成就 / 技能 / 收藏）
```

- 阈值 60–80px；指示条用现有配色；
- 与 iOS 左缘返回手势互斥：只认垂直位移（`dy>0`，横向 <30px）；
- `overscroll-behavior-y: contain` 防系统回弹干扰。

**验收**：各列表页下拉 → 指示条出现 → 松手刷新；上下不再露灰边。

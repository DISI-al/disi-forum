## 一、已定方案 / 待实施

### 1. 打卡卡结算与进化　`待实施`
方案见 [`INSIST-打卡卡结算设计.md`](./INSIST-打卡卡结算设计.md)，要点：

- 判定：连续满 `cycle_days`（完美）/ 累计满（补满）→ 自动结算；任意时刻可手动结算；
- 结算动作：`kind: checkin → task`、`status: done`、锁定 XP、`detail` 自填或自动生成「N 天打卡」；
- 系统**不改**技能重要度；
- 结算后不能打卡 / 完成 / 改周期，只能删除；在技能「关联经验卡」里可见。

### 2. `habit` → `checkin` 改名（含数据库）　`待实施`
- `UPDATE insist_cards SET kind='checkin' WHERE kind='habit'`；
- `UPDATE insist_xp_events SET source='checkin' WHERE source='habit'`；
- **表名一起改**：`insist_habit_logs` → `insist_checkin_logs`（`ALTER TABLE ... RENAME TO`），同步 models、查询、建表清单、导出；
- 影响面 59 处（见设计文档第 9 节）。

### 3. 成就系统（独立大待办）　`待设计`
现状：只有零散 `_award()`（连续 7/30/100、累计 30/100/150/200、完成 10/30/100 张卡），没有定义表、没有首次类成就、成就墙无分组。

目标（仿游戏）：

- **定义表**：`id / 名称 / 描述 / 分类 / tier(1-4) / 条件类型 / 阈值 / 隐藏`；
- **事件引擎**：业务动作 → 事件 → 匹配 → 去重 → 发放（写 `kind='achievement'` 卡）；
- **覆盖**：打卡（连续 / 累计 / 周期全满）、任务（首个任务卡完成、累计 10 张）、项目（首个项目完成、臻阶项目）、技能（首次晋升、达到专家、XP 破千）、记录（首发论坛帖、10 篇周报）、隐藏成就；
- **成就墙**：按分类分组、按 tier 排序、未解锁灰显 + 进度（3/10）。

### 4. 技能升级 / 晋升系统　`部分完成 + 有阻断缺陷`

**已有**

| 能力 | 状态 |
|---|---|
| 初识 → 入门 → 熟练：XP 打满自动升级（含溢出结转） | ✅ |
| 熟练 → 精通 → 专家：手动晋升 + 按量清单 | ✅ |
| 技能页展示等级、XP 进度、遗忘度、溢出、关联经验卡、晋升清单进度条 | ✅ |
| 晋升触发成就 | ❌ 有 bug（#002） |

**缺口（记录，后续补）**

1. 没有升级时间线 / 历史；
2. 接近晋升时无提示（只有满足后按钮亮）；
3. `levelMin` 可配置但前端未逐项暴露；
4. 降级规则未定义（遗忘度只影响显示）；
5. 晋升清单文案与实际计算不一致（#003）。
